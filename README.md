# Currency Note Lab (Fake Currency Detector)

A college project demonstrating an image-classification workflow for Indian currency notes. Upload a note image, view the model's label and score, then browse locally saved scans and PDF reports.

> **Educational use only.** This is not a legal, forensic, or bank-grade authenticity checker. The current interface is scoped to **₹500 notes**. Predictions can be wrong; never use them to accept or reject currency.

## Important scope

- The current trained model uses a limited set of ₹500 note images.
- The trained model file is **not included** in this GitHub repository. A fresh clone runs in **Demo mode**, with simulated results so you can explore the workflow. Demo results are not model predictions.
- To use trained inference, train a model or obtain the project checkpoint, then place `currency_model.keras` and its matching `class_names.json` in `models/`. Install TensorFlow in the same Python environment that runs the server.
- A model score is not a probability of authenticity. The model cannot inspect UV response, microprinting, paper, or security threads.

## Features

- Upload or drag and drop JPG, PNG, WEBP, or BMP images up to 10 MB.
- Display an image-model label and score with educational-use warnings.
- Save scans, images, and PDF reports locally.
- Browse, filter, and delete scan history.
- Run in Demo mode without TensorFlow or model weights.
- Train a MobileNetV2 transfer-learning model with TensorFlow/Keras.

## Run locally from GitHub (Windows 10/11)

### 1. Install prerequisites

Install **Git** and **Python 3.11**. During Python setup, enable the option to add Python to PATH. Check the commands in PowerShell:

```powershell
git --version
py -3.11 --version
```

### 2. Clone the repository

```powershell
cd $HOME\Desktop
git clone https://github.com/PrakashMN/Fake-currency.git
cd Fake-currency
```

### 3. Create an environment and install app dependencies

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

These are the lightweight dependencies for the web app. TensorFlow is not required for Demo mode.

### 4. Start the app

```powershell
.\run.bat
```

Keep the terminal open while using the app. The launcher starts the server at `http://127.0.0.1:8000` and installs app requirements if needed. You can also run `.\run.ps1` from PowerShell.

### 5. Open and check it

- App: <http://127.0.0.1:8000>
- Model status: <http://127.0.0.1:8000/api/model>
- API health: <http://127.0.0.1:8000/api/health>
- Interactive API docs: <http://127.0.0.1:8000/docs>

A fresh clone reports `"mode":"demo"` at `/api/model` because the trained checkpoint is not in Git. Press **Ctrl+C** in the terminal to stop the server.

### Optional: macOS or Linux

Install Python 3.11 and Git, then run from the cloned project directory:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python -m uvicorn backend.main:app --reload --host 127.0.0.1 --port 8000
```

Then open <http://127.0.0.1:8000>.

## Use a trained model

The app needs **both** files below in `models/`:

```text
models/
├── currency_model.keras
└── class_names.json
```

1. Install TensorFlow into the same environment used to start the server:

   ```powershell
   .\.venv\Scripts\python.exe -m pip install -r requirements-ml.txt
   ```

2. Copy the trained `currency_model.keras` and matching `class_names.json` into the local `models/` folder. Create that folder if needed.
3. Stop and restart the server.
4. Visit <http://127.0.0.1:8000/api/model>. Confirm it reports `"mode":"trained"` and `"error":null`.

If status still says `demo`, check that both files are in the correct folder and that TensorFlow was installed in the Python environment running the server.

## Train a model

### Dataset and folder layout

Dataset images are not included in this repository. One possible source is the [Indian Currency Dataset on Kaggle](https://www.kaggle.com/datasets/ashish2k22a318/indian-currency-dataset). Review the source page's license and attribution requirements before using it. This dataset contains ₹500 note images only.

Arrange training images in exactly two class folders:

```text
data/
└── dataset/
    ├── fake/
    │   └── *.jpg
    └── real/
        └── *.jpg
```

Keep the class folders named `fake` and `real`. Do not commit private, unlicensed, or large dataset files. When creating train/test splits, keep augmented copies of the same original note together; near-duplicates across splits can inflate scores.

### Install and run training

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-ml.txt
.\.venv\Scripts\python.exe -m backend.train --data data/dataset --output models/currency_model.keras --epochs 12 --fine-tune --fine-tune-epochs 4 --batch-size 16
```

The first training run needs internet access to download MobileNetV2's ImageNet starting weights. A GPU (for example, Google Colab) makes training faster. The script saves `models/currency_model.keras` and `models/class_names.json`.

**Evaluation note:** the training script reserves a random file-level validation split. It does not create a separate group-held-out test set. If the dataset contains augmented copies, split by original note before training and evaluate on untouched original images. Do not present validation accuracy as real-world accuracy.

### One small evaluation run

One small held-out run on 48 usable images (23 fake, 25 real) classified 44 correctly (91.7% accuracy). Fake recall was 19/23 (82.6%); real recall was 25/25 (100%). Four fake test images were labelled real. This small test set is not representative of real-world currency, and the numbers are not a performance guarantee.

## How the app works

1. The browser sends an image and denomination to FastAPI.
2. The server checks file type and size, corrects EXIF rotation, converts to RGB, and stores a normalized copy locally.
3. If a trained model is available, it resizes the image to the model input size and classifies it as `fake` or `real`. Otherwise, it returns a clearly labelled simulated Demo result.
4. The result, score, timestamp, and image path are stored in `detections.db` (SQLite).
5. A PDF is generated under `reports/`; uploaded images are stored under `uploads/`.
6. The page refreshes the summary and history.

Scans and reports stay on the machine running the app; the project does not upload them to a hosted service.

## Common problems

- **`git` or `py` is not recognized:** install Git or Python 3.11, reopen PowerShell, and retry.
- **Port 8000 is in use:** stop the other server or change the port in `run.ps1` and use the matching URL.
- **The page does not open:** confirm the launcher terminal says Uvicorn is running and open `http://127.0.0.1:8000`.
- **Model status says `demo`:** expected without model weights. For trained mode, install `requirements-ml.txt` in the server's environment, add both files under `models/`, and restart.
- **History is empty:** scan an image, or run the optional sample-data command below.

To populate the dashboard with clearly marked preview records:

```powershell
.\.venv\Scripts\python.exe seed_demo.py
```

These are generated illustrations, not genuine currency photographs or model results.

## Likely college viva questions and answers

### 1. What is the purpose of this project?

It demonstrates an end-to-end image-classification app: image upload, model inference, local history, and PDF reporting. It is an educational prototype, not an official counterfeit-detection system.

### 2. Which model does it use?

MobileNetV2 transfer learning. The ImageNet-pretrained feature extractor is paired with a two-class output layer for `fake` and `real`.

### 3. Why choose MobileNetV2?

It is a compact convolutional network that is practical for a student project and reuses pretrained visual features instead of learning everything from a small dataset.

### 4. What is transfer learning?

Transfer learning reuses a model trained on a large dataset for a related task. This project first trains a small classifier head, then can fine-tune the last MobileNetV2 layers.

### 5. What does image preprocessing do?

Images are converted to RGB and resized to 224 × 224 for the model. The server corrects EXIF rotation and limits upload size; the model rescales pixel values internally.

### 6. Why use data augmentation?

Random flips, small rotations, zoom, and contrast changes add image variation and may reduce overfitting. Augmentation does not replace collecting diverse, correctly labelled notes.

### 7. What is the difference between training, validation, and test data?

Training data updates model weights. Validation data helps monitor training and choose settings. A separate untouched test set estimates performance after training; augmented variants of the same note should not cross the train/test boundary.

### 8. What were the test results?

One small held-out run scored 91.7% on 48 images. It detected 19 of 23 fake images (82.6% fake recall) and 25 of 25 real images. Four fake test images were missed, so this is not safe for authenticity decisions.

### 9. Does 92% confidence mean a 92% chance that the note is genuine?

No. It is the model's top class score, not a calibrated probability of authenticity. The model can be confidently wrong.

### 10. What are false positives and false negatives?

A false positive is a real note labelled fake. A false negative is a fake note labelled real. The small evaluation run had four false negatives, which is one reason not to use this app to verify currency.

### 11. Why does the current app support only ₹500?

The dataset and model are limited to ₹500 notes. The model does not predict denomination, so the interface does not imply support for other notes.

### 12. What is Demo mode?

Demo mode lets someone explore the upload and report workflow without a trained model. Its results are simulated and must not be presented as model predictions.

### 13. Why use FastAPI?

FastAPI provides the Python API that receives images, calls the model, saves results, and serves interactive API documentation.

### 14. Why use SQLite?

SQLite stores local scan history in one lightweight database file, so the project does not need a separate database server.

### 15. Where are scans and reports stored?

The database is `detections.db`; uploaded image copies go in `uploads/`; generated PDFs go in `reports/`. These are local runtime data and are not committed to Git.

### 16. What are the main limitations and future improvements?

The model uses a small image dataset and cannot inspect physical security features. Future work could collect more licensed note images, add denominations, create group-separated test sets, improve score calibration, and evaluate on independent images.

## Safety reminder

Never rely on this app to determine whether a banknote is genuine. Use it only to demonstrate the software and machine-learning workflow.
